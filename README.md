# Local AI

手元の PC で動くローカル LLM（Ollama）と、クラウドの Gemini API を1つの画面で切り替えて使えるデスクトップ AI チャットアプリです。
会話はすべて PC 内に保存され、ローカルモデルを使う限りインターネットにデータを送りません。

![チャット画面](docs/images/chat.png)

## 主な機能

- **ローカル LLM とチャット**（Ollama）: ストリーミング表示・生成の途中停止・思考プロセス（reasoning）の折りたたみ表示
- **Gemini API とチャット**: モデル一覧から選ぶだけでクラウドモデルに切り替え
- **Markdown / コード表示**: シンタックスハイライト、コードのコピー・ファイル保存
- **画像・テキストファイルの添付**: ドラッグ＆ドロップ／貼り付けに対応（画像対応モデルで画像を読ませる）
- **ネット検索**: 検索結果を回答の根拠として渡す
- **音声入力・読み上げ**: Web Speech API を使用
- **会話履歴**: 複数スレッドの保存・切り替え・Markdown ファイルへの書き出し
- **モデル管理**: 16GB VRAM 向けのおすすめモデルのダウンロード（進捗表示）・不要なモデルの削除
- **VRAM 使用量メーター**: モデルが GPU に収まっているか、メインメモリにはみ出していないかを表示
- **モデルに合わせたテーマ**: 選んだモデル（Gemini / Qwen / DeepSeek / Llama / Mistral など）に合わせて配色が自動で切り替わる
- **設定**: コンテキスト長・送る履歴の件数・システムプロンプト

![モデル管理画面](docs/images/models.png)

## 技術スタック

- **Electron**（デスクトップアプリ化）+ **React 19** + **Vite**
- **Ollama REST API**（`/api/chat` のストリーミング、`/api/pull`・`/api/delete`・`/api/ps`）
- **Gemini API**（Server-Sent Events のストリーミング）
- **marked** + **DOMPurify**（Markdown の描画と XSS 対策）、**Prism.js**（コードのハイライト）

## なぜこう作ったか（設計判断）

このアプリは **「AI の出力や Web ページの中身は信用できない入力として扱う」** ことと、**「16GB の GPU で、ローカル LLM を快適に使う」** ことの2つを軸に設計しました。

### セキュリティ

#### 1. 通信はすべてメインプロセスを通す

- **課題**: 画面（レンダラー）には、AI の回答や検索結果を HTML として表示します。もしそこに悪意のあるスクリプトが紛れ込むと、画面側から PC のファイルや任意の通信先に手が届いてしまいます。また、`file://` で開いた画面から Ollama に直接アクセスすると、CORS（ブラウザのオリジン間通信の制限）に引っかかります。
- **判断**: 画面側は `contextIsolation: true` / `nodeIntegration: false` にして Node.js の機能を一切持たせず、`preload.js` の `contextBridge` で公開した決まった関数（IPC）だけを呼べるようにしました。実際の通信はすべてメインプロセスが代わりに行います。
- **理由**: 画面側が乗っ取られても、できることが「用意した関数を呼ぶ」だけに限られます。CORS の問題も、通信をメインプロセスに寄せることで同時に解決できます。

#### 2. 通信先を許可リストで制限する（SSRF 対策）

- **課題**: メインプロセスは画面側から「この URL に送って」と頼まれて通信します。そのままだと、画面側の不具合や乗っ取りによって、社内ネットワークや任意のサーバーへの通信（SSRF）に悪用されたり、API キーを外部に送らされたりするおそれがあります。
- **判断**: 通信してよい相手を、ローカルの Ollama（`127.0.0.1:11434`）と Gemini API の公式ホスト（`generativelanguage.googleapis.com`、HTTPS のみ）に限定しました。それ以外の宛先はメインプロセスが拒否します。
- **理由**: 「何を禁止するか」を列挙する方式では抜け漏れが出ます。「何を許可するか」を列挙すれば、想定外の宛先は自動的にすべて止まります。

#### 3. API キーは OS の仕組みで暗号化し、URL にも載せない

- **課題**: Gemini の API キーを `localStorage` や設定ファイルに保存すると、PC 内に平文で残ります。また、URL のクエリ（`?key=...`）に入れると、ログやエラーメッセージにそのまま表示されることがあります。
- **判断**: Electron の `safeStorage`（Windows では DPAPI）で暗号化して保存し、画面側ではなくメインプロセスだけが復号します。送るときは URL ではなく `x-goog-api-key` ヘッダーに入れます。
- **理由**: DPAPI は Windows のログインユーザーに結び付いた暗号化なので、ファイルをコピーされても別のユーザーや PC では復号できません。
- **引き換えにしたこと**: 別の PC に移すと、キーを入れ直す必要があります。これは持ち出せないことの裏返しなので、意図どおりの動きです。

#### 4. Markdown は無害化してから表示する

- **課題**: AI の回答はもちろん、ネット検索で取り込んだ Web ページの文章にも、HTML や `<script>` が含まれている可能性があります（検索結果を使ったプロンプトインジェクションなど）。
- **判断**: `marked` で HTML に変換したあと、必ず `DOMPurify` を通してから画面に描画します。リンクはアプリ内では開かず、既定のブラウザに渡します。
- **理由**: 1・2 の対策があっても、画面そのものが壊されないことが第一の防御線になるためです。

### ローカル LLM を快適に使うための工夫

#### 5. VRAM メーターは推測ではなく実測値を使う

- **課題**: モデルが GPU メモリ（VRAM）に収まりきらないと、一部がメインメモリにはみ出し、生成速度が大きく落ちます。しかし、利用者からはそれが見えません。
- **判断**: Ollama の `/api/ps` からモデルが実際に使っている VRAM 量（`size_vram`）を取得して表示し、`size > size_vram` のとき（はみ出しているとき）は赤色で「VRAM不足（RAMへ退避中・低速）」と表示します。モデルを読み込む前は、サイズから推定した値を表示します。
- **理由**: 「なぜか遅い」の原因を、その場で目で見て分かるようにするためです。

#### 6. モデルをメモリに長く残す（`keep_alive: 30m`）

- **課題**: Ollama の既定では、5分使わないとモデルが VRAM から外れます。そのため、少し時間を置いて質問するたびに再読み込み（約5秒）の待ち時間が発生していました。
- **判断**: チャットのリクエストで `keep_alive` を30分に延ばしました。
- **引き換えにしたこと**: その間 VRAM を占有し続けます。チャット専用のアプリなので、応答の速さを優先しました。

#### 7. コンテキスト長の既定値と「思考」の扱い

- **課題**: 思考（reasoning）するモデルは、考えるだけで数千トークンを使います。当初の既定値（3072）では、会話の冒頭にあるシステムプロンプトが切り捨てられていました。
- **判断**: 既定値を 8192 に引き上げました（古い設定を持つ利用者は、一度だけ自動で引き上げます）。さらに、過去の回答の「思考プロセス」部分は、次の質問を送るときの履歴から除外しています。
- **理由**: 実測で、gpt-oss:20b はコンテキストを 8192 → 16384 にしても VRAM 使用量がほとんど変わりません（約11.9GiB）。一方、過去の思考は回答にほぼ不要で、コンテキストを大きく消費します。

#### 8. ストリーミング表示を途切れさせない・重くしない

- **課題**: 通信の区切りが JSON 行の途中に来ると、その行を読み飛ばして回答の一部が欠けていました。また、1トークンごとに画面を描き直すと、80 tok/s を超えるモデルでは描画が追いつきません。
- **判断**:
  - 受信データは改行が来るまでためておき、完成した行だけを処理します。
  - 画面の更新は1フレーム（約16ms）に1回へ間引きます。
  - 会話の保存も、生成中は少し待ってまとめて書き込みます。
  - 「生成停止」を押したときは接続そのものを切ります。
- **理由**: 接続を切れば、Ollama 側も推論をやめます。画面の表示だけを止めると、GPU が裏で回り続けてしまうためです。

### 使い勝手と割り切り

#### 9. ネット検索は API キー不要の方式にする

- **判断**: 検索 API ではなく、Yahoo! JAPAN の検索結果ページを取得して、上位4件のタイトル・URL・概要を取り出します。10秒で応答がなければ打ち切ります（回答が止まったままにならないように）。また、検索の有無にかかわらず、システムプロンプトには毎回今日の日付を入れています。LLM が学習時点を「今」と取り違えて、古い情報を最新として答えるのを防ぐためです。
- **理由**: 利用者に追加の登録や API キーを求めずに、「最新の情報について聞く」を実現するためです。
- **引き換えにしたこと**: 検索ページのデザインが変わると、取り出し処理が壊れる可能性があります。そのため、1件ずつ独立して解析し、一部が崩れても残りは使えるようにしています。

#### 10. 会話履歴は PC 内（localStorage）に保存する

- **理由**: サーバーを持たず、会話を外に出さないためです。ローカルモデルを使う限り、データは PC の外に一切出ません。
- **引き換えにしたこと**: `localStorage` には約5MBの上限があり、画像を多く添付すると上限に達します。その場合もアプリは止めず、警告だけを出します。大事な会話は Markdown ファイルに書き出して保存できます。

#### 11. 起動を速くする

- **判断**: 起動のたびに開発サーバー（Vite）を立ち上げるのではなく、ビルド済みの `dist/` を直接読み込みます。ソースが更新されたときだけ、起動前に自動で再ビルドします（`scripts/ensure-build.js`）。
- **理由**: 普段使いのデスクトップアプリとして、アイコンを押してすぐ使えることを優先しました。

## セットアップ（Windows 10 / 11）

1. [Node.js 20 以上](https://nodejs.org/)をインストール
2. [Ollama](https://ollama.com/download) をインストール
3. このリポジトリをダウンロード（`git clone` または ZIP）
4. **`setup.bat` をダブルクリック**
   ライブラリのインストール → 画面のビルド → デスクトップにショートカット作成、まで自動で行います。
5. デスクトップの「Local AI」から起動し、左下の「モデル管理」でモデルを導入

`launch.bat` は、Ollama が起動していなければ起動してからアプリを開きます。

### Gemini を使う場合

[Google AI Studio](https://aistudio.google.com/apikey) で API キーを発行し、アプリの「設定」に入力してください（暗号化して PC 内に保存されます）。

### 開発用コマンド

```bash
npm run dev:app   # Electron + Vite 開発サーバー（別ターミナルで npm run dev）
npm run build     # dist/ を再ビルド
npm start         # 必要ならビルドしてから起動
```

## フォルダ構成

```
main.js              Electron メインプロセス（Ollama / Gemini 通信の中継、検索、ファイル保存、API キー管理）
preload.js           レンダラーに公開する IPC
src/
  App.jsx            状態管理（スレッド・設定・モデル選択・VRAM 計算）
  components/        ChatArea / Sidebar / ModelManager / SettingsModal
  utils/ollamaApi.js Ollama・Gemini API のラッパー（ストリーミング処理）
scripts/ensure-build.js  起動前の差分ビルド
```

## 動作環境の目安

おすすめモデルの一覧は **NVIDIA GPU・VRAM 16GB** を想定しています。VRAM が少ない PC では、`ollama pull qwen3:4b` などの小さいモデルを使ってください。
